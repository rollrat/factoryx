# FactoryX 월드·환경 극한 디테일 제작 파이프라인

> - 문서 상태: 제작 기준 v0.1
> - 프로젝트: FactoryX / 행성 A-17
> - 상위 문서: `environment-world-design.ko.md`, `machine-visual-design-principles.ko.md`
> - 적용 범위: 지형, 절벽, 수계, 동굴, 하늘, 날씨, 암석, 식생, 랜드마크, 환경 재질, Blender 자산, World Studio, Three.js 런타임
> - 핵심 목표: 1인칭 근거리에서 설득력 있는 표면과 구조를 제공하면서 오버뷰에서는 바이옴과 생산 동선이 선명하고, 웹 브라우저에서 60fps를 유지한다.
> - 기본 방침: 극한 디테일은 무작위 소품 수나 폴리곤 수가 아니라 **큰 형태의 설계, 물리적 인과, 거리별 정보 분리, 재질 반응과 안정적인 LOD**로 만든다.
> - 첫 적용 단위: 현재 World Studio의 `256×256m` 제작형 섹터. 더 큰 월드는 이 기준을 통과한 뒤 스트리밍 가능한 섹터 묶음으로 확장한다.

## 1. 문서의 목적

이 문서는 “환경을 더 자세하게 만든다”를 실제 제작 가능한 규칙으로 바꾼다. 최종 결과는 다음 조건을 동시에 만족해야 한다.

1. 1인칭에서 지면, 절벽, 물, 암석과 식생이 임시 프리미티브로 보이지 않는다.
2. 오버뷰에서 공장, 지형, 자원과 물류 경로가 환경 디테일에 묻히지 않는다.
3. 색을 제거해도 여섯 바이옴의 지형 실루엣과 군락 구조가 구분된다.
4. 모든 균열, 침식, 젖음, 먼지, 식생 방향과 암석층에는 위치적 이유가 있다.
5. 플레이 영역과 원경 사이에 빈 공간, 검은 구멍, LOD 균열과 갑작스러운 팝이 없다.
6. Blender 원본, World Studio 제작 데이터와 Three.js 런타임이 하나의 반복 가능한 파이프라인으로 연결된다.
7. 고품질 프리셋은 데스크톱에서 60fps, 저품질은 30fps 이상을 목표로 한다.

이 문서에서 말하는 디테일은 사실성을 높이는 정보다. 화면을 복잡하게 만드는 정보는 디테일로 간주하지 않는다.

이 문서의 “오브젝트”는 암석, 식생, 절벽, 동굴, 랜드마크와 환경 접합물을 중심으로 한다. 생산 설비의 기능 실루엣과 공정 동작은 `machine-visual-design-principles.ko.md`와 `production-lineage-design.ko.md`가 우선하며, 단위·LOD·GLB·재질·검증 파이프라인은 이 문서의 공통 규격을 따른다.

## 2. 품질 정의

### 2.1 세 단계 형태 계층

환경과 오브젝트는 항상 다음 세 단계로 제작한다.

| 단계 | 화면 역할 | 환경 예시 | 오브젝트 예시 |
| --- | --- | --- | --- |
| 큰 형태 60% | 위치와 정체성을 결정 | 분지, 고원, 협곡, 수계, 동굴 입구 | 암석군 외곽, 수관, 랜드마크 전체 실루엣 |
| 중간 형태 30% | 형성 원인과 구조를 설명 | 층리, 침식 홈, 절벽 분절, 하안단구 | 암석 파단면, 뿌리, 관절, 겹판, 기부 |
| 작은 형태 10% | 근거리 재질과 사용감을 보강 | 자갈, 미세 균열, 물때, 퇴적선 | 표면 홈, 작은 잎맥, 마모, 포자, 이음부 |

큰 형태가 통과하기 전에는 작은 디테일을 추가하지 않는다. 랜드마크가 원뿔로 보이는 상태에서 표면 노멀을 추가하는 작업은 품질 향상이 아니다.

### 2.2 거리별 정보 계약

| 거리 | 반드시 읽혀야 하는 정보 | 제거해야 하는 정보 |
| --- | --- | --- |
| 0~4m | 표면 거칠기, 접합, 두께, 젖음 경계, 작은 변형 | 반복이 보이는 큰 타일 패턴 |
| 4~12m | 암석 파단, 식생 구조, 배수 방향, 충돌 형태 | 개별 볼트 수준의 무의미한 소품 |
| 12~35m | 암반·식생 군락, 절벽 층, 수계 외곽, 오브젝트 종류 | 미세 데칼과 얇은 가지 |
| 35~90m | 바이옴의 대표 실루엣, 고저차, 랜드마크, 공장 동선 | 작은 그림자 캐스터와 투명 재질 |
| 90~220m | 연결된 능선, 고원 외곽, 대형 수면, 세계 방향성 | 개별 돌·식생 애니메이션 |
| 220m 이상 | 낮은 빈도의 원경 산맥과 대기 원근 | 규칙적인 원뿔, 반복 군락, 고주파 노이즈 |

LOD는 단순히 삼각형을 줄이는 기능이 아니라 각 거리에서 필요 없는 정보를 제거하는 기능이다.

### 2.3 물리적 인과 원칙

- 높은 곳의 노출 암반은 날카롭고 건조하며, 낮은 곳은 퇴적물과 수분이 축적된다.
- 균열은 경사, 암석층, 열극 또는 구조적 응력 방향을 따른다.
- 젖음은 수위, 배수 홈, 식생 기부, 그늘과 설비 누수 아래에만 나타난다.
- 먼지는 바람을 맞는 면보다 바람 뒤쪽, 기초 모서리와 정체 영역에 쌓인다.
- 식생은 수분, 고도, 경사와 바람 차폐에 반응한다.
- 절벽 파편은 절벽 하부에 집중되고 능선 정상에 균일하게 흩어지지 않는다.
- 공장 근처 환경 변화는 설비 종류, 배기 방향과 실제 점유 면적을 따른다.

## 3. 목표 화면과 금지 항목

### 3.1 목표 화면

- 맑은 날은 지구와 유사한 파란 하늘, 흰 고층 구름과 깨끗한 원경을 기본으로 한다.
- 외계성은 주황 안개가 아니라 지질, 식생 구조, 위성, 약한 궤도 띠와 열극 현상에서 만든다.
- 시작 분지는 공장을 놓을 만큼 열려 있지만 평평한 개발판처럼 보이지 않는다.
- 절벽은 실제 수직면과 층리 구조를 가지며 지면 색만 어두워진 경사로 대체하지 않는다.
- 습지는 실제 수면, 해안선, 진흙, 수생 식생과 반사를 가진다.
- 동굴은 외부에서 본 원통이 아니라 내부에서 이동하고 건설할 수 있는 닫힌 공간으로 보인다.
- 랜드마크는 하나의 원뿔이나 토러스가 아니라 고유한 덩어리, 축과 파단 리듬을 가진다.

### 3.2 금지 항목

- `floor()`로 양자화한 셀 노이즈를 높이에 직접 더하지 않는다.
- 이웃 LOD 경계가 서로 다른 높이 표본을 사용하게 하지 않는다.
- 산맥을 동일한 원뿔 수십 개의 원형 배열로 만들지 않는다.
- `submerged` 지면을 어둡게 칠한 것만으로 물을 표현하지 않는다.
- 검은 불투명 원판을 젖음, 먼지 또는 그림자로 사용하지 않는다.
- 모든 바이옴에 같은 높이 함수와 같은 소품 비율을 적용하지 않는다.
- 1인칭 카메라에서 보이는 절벽, 동굴과 랜드마크를 코드 프리미티브만으로 최종 제작하지 않는다.
- 한 오브젝트에 전용 4K 텍스처를 무조건 배정하지 않는다.
- 고품질을 이유로 화면 전체에 같은 빈도의 미세 디테일을 채우지 않는다.

## 4. 제작 도구와 권한 분리

### 4.1 권장 도구 구성

| 도구 | 소유할 데이터 | 담당 작업 |
| --- | --- | --- |
| 게임 코드 | 결정적 높이·경사·표면·충돌 계산 | 지형 샘플링, 건설 판정, LOD, 저장, 런타임 상태 |
| World Studio | 월드 배치와 마스크 | 바이옴, 수계, 절벽선, 건설 구역, 자원, 랜드마크, 카메라 검수 |
| Blender | 실제 3D 자산 | 절벽, 동굴, 암석, 식생, 랜드마크, 충돌, LOD, UV, 애니메이션 |
| Gaea 선택 | 오프라인 높이·침식 데이터 | 기본 높이맵, 유수·침식·퇴적·경사 마스크 |
| Three.js | 최종 조립 | glTF 로딩, 인스턴싱, 재질, 그림자, 물, 하늘, 스트리밍 |

Houdini는 여러 대형 맵을 반복 생산하거나 절차 제작팀이 생기기 전에는 도입하지 않는다. 첫 완성 맵은 Blender, World Studio와 코드 생성기로 충분히 제작한다.

### 4.2 소스 오브 트루스

- 높이, 바이옴, 수계, 절벽선과 건설 규칙의 최종 정의는 버전 관리되는 월드 데이터다.
- 결정적 CPU `TerrainSampler`가 높이, 법선, 경사, 표면, 수심, 건설 가능 여부와 지층 ID의 단일 진실 원천이다. 렌더 메시, 레이캐스트, 1인칭 충돌과 배치 프리뷰는 모두 이 샘플러에서 파생한다.
- Blender 파일은 오브젝트 형상과 LOD의 원본이다.
- `.glb`는 런타임 전달물이며 수동 수정하지 않는다.
- World Studio는 런타임과 동일한 월드 데이터를 읽고 쓴다.
- 저장 파일에는 원본 지형과 메시를 복사하지 않고 환경 버전과 플레이어 델타만 저장한다.

## 6. 좌표와 단위 계약

- Three.js와 Blender 모두 1 단위를 1m로 사용한다.
- 게임 월드는 `Y-up`이며 지면 평면은 `X/Z`다.
- Blender 원본은 Z-up이므로 glTF 내보내기 변환을 일관되게 적용하고 런타임에서 추가 보정 회전을 만들지 않는다.
- 모든 정적 오브젝트는 배치 기준점을 바닥 접촉면 중앙에 둔다.
- 절벽 모듈은 스플라인 접합 방향을 `+X`, 전면을 `+Y` 같은 별도 규약으로 고정하고 export script가 검증한다.
- 회전·스케일을 적용한 뒤 내보내며 음수 스케일은 금지한다.
- 충돌 메시와 시각 메시의 원점, 축과 바운드는 동일해야 한다.
- 사람 기준 1.75m, 건설 타일 1m, 벨트 폭과 포트 높이는 기존 게임 계약을 그대로 사용한다.

## 7. 하이브리드 지형 생성 파이프라인

### 7.1 최종 표현

현재 256×256m 섹터는 무한 지형 알고리즘보다 제작된 고정 월드가 적합하다.

- 기준 높이 원본: 513×513 표본, 0.5m 간격의 16비트 그리드
- 원본 데이터 크기: 약 0.5MiB
- 전체를 한 번에 LOD0로 만들 경우: 약 263k 정점, 524k 삼각형
- 실제 렌더: 카메라 주변 청크만 LOD0로 만들고 바깥은 단계적으로 축소
- 지형 데이터: 16비트 높이 또는 정규화된 부동소수 그리드
- 바이옴: 여섯 채널 가중치 또는 압축된 상위 두 바이옴+혼합값
- 별도 마스크: 물, 절벽, 연약 지반, 위험, 도로, 조사 패드, 자원 보호 구역

0.5m 표본보다 작은 표면 정보는 지오메트리가 아니라 노멀, 거칠기, 버텍스 컬러, 데칼과 소품으로 표현한다. 0.5m 원본은 충돌과 토공의 정밀도를 위한 것이며 모든 청크를 최고 해상도로 그리라는 뜻이 아니다.

### 7.2 생성 순서

```text
수제 거시 레이아웃
→ 연속 기본 노이즈
→ 바이옴별 거시 지형 연산
→ 수계와 침식
→ 절벽·열극 마스크
→ 건설지·도로 grading
→ 자원 접근 경로 보정
→ 재질·소품 파생 마스크
→ LOD 생성과 연속성 검증
```

#### 1단계: 수제 거시 레이아웃

먼저 다음 요소를 World Studio에서 저해상도 마스크로 확정한다.

- 시작 분지 외곽
- 여섯 바이옴의 중심과 연결 방향
- 주 능선, 협곡과 고원 외곽
- 주요 수로, 습지와 수위
- 동굴 입구 두 곳과 지하 경로
- 자원 앵커와 안전한 첫 접근로
- 프로젝트 도크, 대규모 공장 후보지와 랜드마크 시야축

노이즈로 레이아웃을 결정하지 않는다. 노이즈는 수제 형태를 자연스럽게 만드는 보조층이다.

#### 2단계: 연속 기본 노이즈

- OpenSimplex2S 또는 동등한 연속 노이즈를 사용한다.
- 큰 형태 48~96m, 중간 형태 12~32m, 작은 형태 3~8m의 세 주파수로 나눈다.
- fBm 옥타브는 3~5개로 제한한다.
- domain warp는 큰 형태의 경계를 깨는 데만 약하게 사용한다.
- 노이즈 진폭은 주파수가 높아질수록 급격히 줄인다.
- 모든 좌표에서 미분 가능한 연속성을 유지한다.
- 시드, 알고리즘 버전과 파라미터를 환경 정의에 저장한다.

권장 시작값은 다음과 같다. 최종 값은 World Studio 프로파일러로 조정한다.

| 층 | 파장 | 높이 진폭 | 역할 |
| --- | ---: | ---: | --- |
| 거시 | 64~96m | 3~9m | 분지, 구릉, 고원 기울기 |
| 중간 | 18~36m | 1~3m | 침식 능선과 골 |
| 소형 | 5~12m | 0.15~0.7m | 지표 불규칙성 |

#### 3단계: 바이옴별 지형 연산

바이옴은 지면색이 아니라 지형 생성 함수에 영향을 준다.

| 바이옴 | 거시 형태 | 중간 형태 | 수분·표면 |
| --- | --- | --- | --- |
| 바람유리 분지 | 열린 얕은 분지와 낮은 풍식 능선 | 한 방향으로 늘어난 낮은 홈 | 건조 기반암, 국소 생물막 |
| 철풍 단층지 | 방향성 단층벽과 긴 협곡 | 탄소층 띠와 낙석 선상지 | 건조, 높은 경사 비율 |
| 규산 돛숲 | 완만한 구릉과 바람 통로 | 군락이 피하는 얕은 골 | 중간 습도, 투과광 식생 |
| 검은수맥 습지 | 낮은 폐쇄 분지와 굽은 수로 | 진흙 섬과 미세 제방 | 실제 수면, 포화 지반 |
| 적철 왕관고원 | 분리된 테이블형 고원 | terrace와 붕괴 사면 | 건조, 고도별 퇴적층 |
| 열극 심층부 | 길게 찢어진 함몰과 천공 | 열수 홈, 결정맥 | 위험 표면, 수증기, 동굴 연결 |

바이옴 가중치는 합이 1이 되게 정규화하며, 전 영역을 최대 50%로 섞지 않는다. 전이대는 보통 8~24m로 두고 큰 지질 경계에서는 30~50m까지 확장한다.

#### 4단계: 수계와 침식

- 수위보다 낮은 모든 지점이 물이 되는 단순 평면 방식을 사용하지 않는다.
- 수체 ID마다 수위, 최대 깊이, 유입·유출, 색과 탁도를 가진다.
- 흐름 누적값으로 수로 후보를 만들고 수제 수계 마스크로 방향을 고정한다.
- 침식은 거시 지형을 무너뜨리지 않고 중간 형태와 퇴적 위치를 만드는 데 사용한다.
- 침식 결과에서 `flow`, `wear`, `deposit`, `wetness` 마스크를 파생한다.
- 도로와 건설지는 침식 뒤 마지막 단계에서 grading한다.

Gaea를 사용할 경우 높이맵만 가져오지 말고 flow, wear, deposit, slope 마스크를 함께 내보낸다.

#### 5단계: 건설지와 경로 grading

- 조사 패드는 지형을 잘라 붙인 정사각형이 아니라 토공 흔적, 배수 홈과 옹벽을 가진다.
- 도로는 중심선 스플라인, 폭, 갓길, 절토·성토 경사를 가진다.
- 자원 패드는 주변 지형과 최소 4~8m 전이 폭으로 연결한다.
- 건설 높이와 렌더 높이는 같은 샘플을 사용한다.
- 모든 필수 자원까지 최소 하나의 4m 이상 폭 안전 경로를 유지한다.

### 7.3 연속성 불변 조건

다음 조건은 자동 테스트로 고정한다.

- 같은 시드와 월드 버전은 모든 품질에서 동일한 높이와 표면을 반환한다.
- 1cm 떨어진 두 표본의 높이차가 의도된 절벽선 밖에서 비정상적으로 뛰지 않는다.
- 청크 공유 경계의 높이, 법선과 바이옴 가중치가 정확히 일치한다.
- LOD 전환 중 지형이 갈라지거나 충돌 높이가 바뀌지 않는다.
- 월드 가장자리까지 지형 또는 원경 연결 메시가 존재한다.
- 저장·불러오기 후 월드 데이터와 플레이어 델타가 동일하게 재현된다.

### 7.4 베이크 산출물 계약

```text
height.r16              513×513, 0.5m 간격
biome-a.ktx2            바이옴 가중치 0~3
biome-b.ktx2            바이옴 가중치 4~5와 보조 채널
surface-mask.ktx2       stable, soft, submerged, hazard, wetness
flow.rg16               유향과 누적 유량
cliff-mask.r8           절벽 후보
cliff-splines.bin       절벽 상·하단과 접합 정보
terrain-collision.bin   높이, 영구 장애물과 건설 제외 영역
caves/<zone>.bin        방·회랑·포털·바닥·천장·건설 볼륨
manifest.json           환경·생성기 버전, seed, bounds와 content hash
```

- 같은 `environmentVersion + generatorVersion + seed`는 byte hash가 같은 산출물을 만든다.
- 저장 파일은 위 산출물을 복사하지 않고 `contentHash`와 제거된 소품·안정화된 위험·열린 포털 같은 플레이 델타만 보관한다.
- 알고리즘이 바뀌어 `contentHash`가 다르면 조용히 새 지형에 기존 공장을 얹지 않고 명시적인 마이그레이션을 요구한다.
- CPU 샘플러와 렌더 정점의 높이 오차는 2cm 이하를 목표로 한다.

## 8. 지형 LOD와 원경

### 8.1 런타임 청크 규격

32m 청크는 다음처럼 `2^n + 1` 정점 규격을 사용한다. 고품질 5×5 활성 범위에서도 가장 가까운 3×3만 LOD0를 유지하고 외곽은 LOD1 이상을 사용한다.

| LOD | 정점 격자 | 표본 간격 | 권장 거리 |
| --- | ---: | ---: | ---: |
| LOD0 | 65×65 | 0.5m | 0~40m |
| LOD1 | 33×33 | 1m | 32~80m |
| LOD2 | 17×17 | 2m | 64~144m |
| Far | 9×9 또는 전용 링 | 4m 이상 | 120~280m |

거리 구간은 겹치게 하고 8~16m 히스테리시스를 둔다.

### 8.2 경계 처리

- 모든 LOD는 고해상도 원본의 동일 좌표를 샘플한다.
- 우선 구현은 청크 외곽에 1.5~3m 지형 skirt를 둔다.
- 이후 공유 edge index와 geomorph를 사용해 팝을 줄인다.
- 법선은 청크 내부 메시만으로 계산하지 않고 높이 샘플의 중앙차분으로 계산한다.
- 저품질에서도 3세그먼트처럼 이웃 LOD와 맞지 않는 격자를 사용하지 않는다.

### 8.3 원경

- 80~220m는 실제 지형 샘플을 사용한 저해상도 far terrain으로 채운다.
- 220m 이후에는 월드 고정형 ridge mesh 3~7개를 사용한다.
- 원경은 카메라를 그대로 추종하지 않고 극히 작은 시차만 허용한다.
- 원경 ridge는 비대칭 실루엣, 높낮이 리듬과 겹침을 가진다.
- 같은 원뿔 메시를 원형으로 반복하지 않는다.
- 오버뷰 카메라 높이에 따라 far terrain 활성 반경을 확장한다.

## 9. 절벽 제작

### 9.1 표현 분리

높이맵은 절벽 상단과 하단을 정의하고 실제 수직면은 별도 메시가 담당한다.

```text
cliff spline
→ 상단·하단 높이 샘플
→ 절벽 띠 메시 생성
→ Blender 절벽 모듈 배치
→ 파편·퇴적·식생 마스크 파생
```

### 9.2 Blender 절벽 키트

각 지질 계열은 최소 다음 모듈을 가진다.

- 직선 8m, 16m, 32m
- 안쪽 코너와 바깥쪽 코너
- 낮은 단차 2~4m
- 중간 절벽 6~12m
- 대형 절벽 12~30m
- 상단 cap, 하단 talus, 균열 삽입물
- 터널·동굴 입구 전환 모듈

모듈 접합부는 눈에 띄지 않도록 겹침 구간과 공용 층리 방향을 가진다. 절벽 전체를 같은 모듈로 채우지 않고 2~4개 큰 리듬으로 나눈다.

### 9.3 절벽 재질

- 월드 공간 또는 triplanar 기반으로 수직면 UV 늘어짐을 방지한다.
- 높이, 경사, 곡률과 습도 마스크로 재질을 섞는다.
- 상단은 풍식과 건조, 하단은 퇴적·이끼·젖음을 강조한다.
- 층리 방향은 바이옴의 지질 축과 일치해야 한다.
- 수직면의 미세 균열은 normal/height로 처리하고 큰 파단은 실제 지오메트리로 만든다.

## 10. 물과 습지

### 10.1 수면 구성

각 수체는 다음 데이터 계약을 가진다.

```text
WaterBodyDefinition
  id
  polygon
  level
  maxDepth
  flowDirection
  turbidity
  colorProfile
  shorelineProfile
```

- 수면은 실제 메시와 셰이더를 사용한다.
- 얕은 곳은 지면색이 보이고 깊은 곳은 흡수색이 강해진다.
- 해안선은 depth fade와 불규칙 wetness 띠를 가진다.
- 반사는 하늘과 큰 랜드마크에 집중하고 작은 소품까지 고비용 반사하지 않는다.
- 수면 법선은 두 크기의 파동을 합성하되 강풍 방향과 일치시킨다.
- 오일막, 산성수, 지열수는 같은 수면 위에 얇은 색·거칠기 변형으로 표현한다.

### 10.2 습지 디테일

- 검은 원형 데칼 대신 연결된 진흙·수로 마스크를 사용한다.
- 수생 식생은 수심과 해안선 거리에 따라 군락으로 배치한다.
- 가스 기포와 증기는 지정된 vent에서만 발생한다.
- 습지의 건설 제한은 수면과 지면 형태만 보고 예측할 수 있어야 한다.
- 물 아래 충돌 지형과 보이는 바닥이 일치해야 한다.

## 11. 동굴 제작

### 11.1 기본 방식

첫 동굴은 복셀이나 실시간 CSG가 아니라 Blender에서 직접 제작한 모듈형 내부 공간으로 만든다.

- 방은 독립 shell 메시다.
- 회랑은 spline sweep 또는 모듈 조합으로 만든다.
- 바닥, 벽과 천장은 끊기지 않는 내부 표면을 가진다.
- 표면 포털은 지형 절개와 동굴 shell을 한 전환 메시로 연결한다.
- 지상과 동굴은 별도 `stratumId`로 유지한다.

### 11.2 동굴 키트

- 폭 6m, 8m, 12m 회랑
- 완만한 상·하행 회랑
- Y 분기, T 분기, 교차
- 소형 보상방
- 중형 물류방
- 대형 공장 공동
- 수직 천공과 갱도 소켓
- 천창·지표 입구 전환
- 열수·방해석·미생물막 삽입물

각 모듈은 시각 메시, 바닥 이동 메시, 건설 가능 볼륨, 천장고와 포털 소켓을 함께 가진다.

### 11.3 동굴 렌더링

- 동굴 진입 시 지상 지형, 원경, 지상 소품, 하늘과 지상 날씨를 렌더 트리에서 제외한다.
- 동굴 전용 fog, 노출, 반사 환경과 로컬 조명을 적용한다.
- 절단 뷰는 지형 전체를 숨기지 않고 clipping plane과 지각 단면을 보여준다.
- 카메라가 있는 방과 인접 방만 렌더링한다.
- 포털을 통하지 않은 지상·동굴 시야 누출을 금지한다.

## 12. 하늘, 구름과 날씨

### 12.1 기본 맑은 하늘

- 파란 천정과 옅은 청백색 지평선을 기본으로 한다.
- 주황색은 일출·일몰의 제한된 시간대에서만 사용한다.
- 대기 안개는 지형을 숨기는 장치가 아니라 거리감을 주는 얇은 층으로 사용한다.
- 기본 맑음 상태에서는 광물 먼지 입자를 거의 보이지 않게 한다.
- ACES 계열 tone mapping과 노출 기준을 고정해 재질 제작 환경을 통일한다.

Three.js `Sky`의 대기 산란을 기본 후보로 사용하고, 프로젝트 팔레트에 맞춘 파라미터를 World Studio에서 조정한다.

### 12.2 구름

- 최소 두 고도층을 사용한다: 얇은 고층운과 중간 고도의 덩어리 구름.
- 맑은 날에도 20~40% 정도의 읽을 수 있는 구름 coverage를 둔다.
- 구름은 단순 사인 띠가 아니라 저주파 coverage와 고주파 edge noise를 가진다.
- 구름 하부는 회청색, 상부는 따뜻한 백색으로 명암을 나눈다.
- 태양 방향에 따라 은은한 역광과 구름 그림자를 제공한다.
- 품질 프리셋에서 해상도, 레이어 수, 그림자 갱신 주기를 함께 조절한다.

### 12.3 날씨 계층

| 상태 | 하늘 | 구름 | 안개 | 지상 입자 |
| --- | --- | --- | --- | --- |
| 맑음 | 파란 대기 | 20~40% | 매우 약함 | 거의 없음 |
| 고층 광물 안개 | 채도 소폭 감소 | 얇은 베일 | 원경에만 증가 | 드문 부유물 |
| 먼지 돌풍 | 지평선만 탁해짐 | 빠른 낮은 층 | 바람 방향 띠 | 국소적으로 강함 |
| 전기 폭풍 | 차가운 회색 | 높은 coverage | 중간 | 비·먼지·전기 섬광 |
| 회복 | 파란색 회복 | 구름 분리 | 빠르게 감소 | 지면 젖음만 잔류 |

날씨는 생산량을 무작위로 감소시키는 시스템이 아니라 환경 상태와 가시성을 전달하는 시스템으로 시작한다.

## 13. Blender 자산 제작 기준

### 13.1 Blender에서 반드시 제작할 자산

- 절벽 모듈과 고원 가장자리
- 동굴 방, 회랑, 입구와 천공
- 모든 바이옴 랜드마크
- 중·대형 암석군
- 복합 식생 실루엣
- 수면 주변 뿌리, 진흙섬과 해안 구조
- 원경 ridge 메시
- 기계와 환경이 만나는 옹벽, 배수구와 산업 지형 모듈

작은 자갈, 얇은 생물막, 먼지와 젖음은 런타임 인스턴스 또는 재질 마스크로 남길 수 있다.

### 13.2 자산 계층

모든 자산은 다음 계층을 따른다.

```text
FX_<asset_id>
├─ VIS_LOD0
├─ VIS_LOD1
├─ VIS_LOD2
├─ COL_SIMPLE
├─ SOCKETS
├─ FX_POINTS
└─ META
```

- `VIS_LOD0`: 1인칭 근거리
- `VIS_LOD1`: 중거리 핵심 구조
- `VIS_LOD2`: 원거리 실루엣
- `COL_SIMPLE`: 단순화된 충돌
- `SOCKETS`: 절벽·동굴·파이프·랜드마크 접합점
- `FX_POINTS`: 증기, 포자, 낙수, 광원 위치
- `META`: 자산 ID와 제작 메타데이터

### 13.3 Blender 커스텀 프로퍼티

```text
fx_asset_id
fx_asset_version
fx_family
fx_biome_ids
fx_lod_level
fx_collision_mode
fx_shadow_distance
fx_wind_response
fx_removable_by_foundation
fx_socket_type
fx_runtime_tags
```

export script는 이 값을 glTF extras로 내보내고 런타임은 필요한 값을 manifest와 교차 검증한다.

### 13.4 모델링 원칙

- 모든 제작 장면에 1.75m 사람, 1m 그리드, 자산 footprint와 카메라 거리 1m/12m/35m/90m 가이드를 둔다. 이 가이드는 export에서 제외한다.
- 먼저 검은 실루엣으로 LOD2를 만든다.
- LOD1에서 파단, 층리, 가지와 기부 같은 중간 형태를 추가한다.
- LOD0에서만 챔퍼, 표면 홈, 얇은 판과 근거리 접합을 추가한다.
- 구조 암반과 굵은 뿌리의 주요 bevel은 실제 20~60mm, 얇은 판과 패널 모서리는 5~15mm에서 시작한다. 화면상 1px도 만들지 못하는 bevel은 노멀로 보낸다.
- LOD0 원통 단면은 화면 크기에 따라 12~24면, LOD1은 8~12면, LOD2는 6~8면을 기준으로 한다.
- 실루엣과 실제 그림자를 바꾸는 균열·파단·판만 geometry로 만든다. 약 10~15mm 이하의 홈, 용접선, 작은 돌기와 흠집은 normal/decal로 처리한다.
- 권장 modifier 순서는 `Mirror/Array → Boolean → Bevel → Weighted Normal → Triangulate`다. 원본을 보존한 임시 export scene에서 적용한다.
- Boolean 결과를 그대로 두지 않고 shading과 topology를 정리한다.
- 모든 노출 모서리에 같은 bevel을 적용하지 않는다.
- 돌은 무작위 구가 아니라 압축, 전단, 층리와 파단 방향을 가진다.
- 식생은 단일 원통이나 원뿔이 아니라 기부에서 2~5개의 구조가 분기한다.
- 얇은 면은 실제 두께 또는 안정적인 double-sided 정책을 가진다.
- 반복 자산은 회전만으로 변형하지 않고 실루엣 변형 3종 이상을 제공한다.
- 128px 검은 썸네일과 90° 네 방향에서 종류, 앞뒤와 접지 방향을 구분할 수 있어야 LOD0 작업으로 넘어간다.

## 14. 오브젝트 디테일 예산

### 14.1 삼각형 예산

| 자산 종류 | LOD0 | LOD1 | LOD2 | 권장 화면 수 |
| --- | ---: | ---: | ---: | ---: |
| 작은 자갈·파편 | 80~300 | 40~120 | 제거 | 100~400 |
| 소형 식생 | 400~1,800 | 180~700 | 40~160 | 40~180 |
| 중형 암석·식생 | 1,500~6,000 | 600~2,400 | 120~600 | 15~60 |
| 대형 암반군 | 6,000~20,000 | 2,000~8,000 | 400~1,500 | 3~18 |
| 절벽 모듈 | 10,000~30,000 | 3,000~12,000 | 600~2,500 | 2~12 |
| 영웅 랜드마크 | 30,000~90,000 | 10,000~35,000 | 2,000~8,000 | 1~3 |
| 동굴 방·회랑 세트 | 20,000~80,000 | 8,000~30,000 | 방 단위 제외 | 인접 2~4방 |

수치는 상한이 아니라 화면 품질을 검증하는 시작 예산이다. 영웅 자산의 실루엣이 20k에서 해결되면 90k까지 늘리지 않는다.

### 14.2 LOD 감소 규칙

- LOD1은 LOD0 삼각형의 약 35~50%를 목표로 한다.
- LOD2는 LOD0의 약 7~15%를 목표로 한다.
- 자동 decimate 결과를 그대로 사용하지 않고 실루엣과 shading을 검사한다.
- 얇은 파츠, 작은 구멍, 내부 면, 미세 변형을 거리 순으로 제거한다.
- 영웅 랜드마크는 billboard보다 전용 저폴리 실루엣을 우선한다.
- 전환 거리는 자산 크기의 화면 점유율을 기준으로 계산하고 종류별 고정값만 사용하지 않는다.

### 14.3 충돌 예산

- 충돌은 렌더 메시를 사용하지 않는다.
- 작은 돌과 식생은 충돌을 만들지 않는다.
- 중형 암석은 1~4개의 convex hull 또는 capsule을 사용한다.
- 대형 절벽은 단순 벽면과 상단 바닥 충돌을 분리한다.
- 동굴은 이동 바닥, 건설 볼륨과 벽 충돌을 별도 데이터로 가진다.
- 반복 자산의 단일 convex hull은 32 vertex 권장, 64 vertex를 상한으로 한다.
- 충돌이 보이는 외곽보다 바깥으로 5cm 이상 튀어나오지 않게 한다. 대형 자연물에서 안쪽 단순화 오차는 0.25m, 절벽과 동굴의 비보행 면은 0.5m까지 허용한다.
- 보행 가능한 바닥, 램프와 동굴 통로는 시각 표면과 충돌 높이 오차를 2cm 이하로 유지한다.

### 14.4 재질과 드로우콜 예산

| 자산 종류 | 재질 슬롯 권장/상한 | 자산당 드로우콜 목표 |
| --- | ---: | ---: |
| 소형·중형 반복 소품 | 1/2 | 1 |
| 대형 암반군·절벽 모듈 | 2/4 | 1~4 |
| 영웅 랜드마크 | 4/8 | 4~8 |
| 동굴 방·회랑 모듈 | 2/5 | 가시 방당 2~5 |

- 볼트, 잎, 작은 파편 때문에 별도 재질이나 draw call을 만들지 않는다.
- 정적 부분은 재질별로 결합하고, 반복 자산은 geometry/material identity를 공유해 `InstancedMesh`로 전환할 수 있어야 한다.
- LOD가 낮아질수록 재질 슬롯 수가 증가하면 검증 실패다. LOD2는 1~3개로 축소한다.
- 자산별 예산보다 화면 전체 예산이 우선한다. 한 자산이 표 안에 있어도 스트레스 장면을 초과하면 더 줄인다.

## 15. UV, 텍스처와 재질

### 15.1 공용 재질군

환경은 오브젝트마다 새 재질을 만들지 않고 다음 공용군을 사용한다.

1. 현무암·탄소 암석
2. 적철·산화 암석
3. 규산염·방해석
4. 토양·진흙·퇴적물
5. 식생 불투명
6. 식생 반투명
7. 물·젖음
8. 발광·특수 반응

### 15.2 텍스처 규격

| 용도 | 기본 해상도 | 비고 |
| --- | ---: | --- |
| 환경 공용 trim/atlas | 2048~4096 | 여러 자산 공유 |
| 영웅 랜드마크 | 2048 | 전용은 예외적으로 허용 |
| 중형 자산 atlas | 1024~2048 | 계열별 공유 |
| 소형 소품 atlas | 512~1024 | 다수 자산 묶음 |
| 데칼 atlas | 1024~2048 | 균열, 퇴적, 젖음 경계 |
| 지형 거시 마스크 | 512~1024 | 바이옴·수계·경사 |

- Base Color는 sRGB, normal과 ORM은 linear로 처리한다.
- Occlusion, Roughness, Metalness는 ORM 텍스처로 패킹한다.
- 텍스처는 KTX2/Basis 압축을 최종 목표로 한다.
- 근접 표면은 256px/m, 시선이 머무는 조작·랜드마크 초점은 512px/m, 후면·하부는 128px/m를 시작값으로 한다.
- 2K atlas의 UV island padding은 최소 12px, 1K는 최소 6px로 두고 1/8 mip에서 bleeding이 없는지 검사한다.
- 환경 계열 표면의 70% 이상은 공용 tile/trim/atlas로 해결한다. 자산 전용 텍스처는 고유 표식, 파단과 희귀 재질에만 쓴다.
- hard edge는 특별한 이유가 없으면 UV seam과 일치시킨다. 방향성 층리·문자·오염이 있는 island는 mirror overlap하지 않는다.
- 노멀맵은 형태를 보완하며 큰 실루엣을 대신하지 않는다.
- 지형과 절벽은 triplanar 또는 월드 공간 재질을 사용해 UV 늘어짐을 줄인다.
- vertex color는 바이옴 변형, 젖음, 풍화와 군락 variation에 사용한다.

### 15.3 데칼 규칙

- 불투명한 원형 데칼을 금지한다.
- 모든 데칼은 feathered alpha 또는 재질 마스크를 사용한다.
- 균열은 지형 경사와 암석층 방향에 맞춘다.
- 먼지와 젖음 데칼은 중복 영역을 union하거나 밀도 제한을 둔다.
- 원거리에서 데칼을 끄고 기반 재질의 거시 마스크만 남긴다.

## 16. 식생과 암석 군락

### 16.1 개별 랜덤보다 군락

소품은 맵 전체에 균일 난수를 뿌리지 않고 다음 단위로 배치한다.

```text
biome patch
→ habitat mask
→ cluster center
→ dominant asset 60~80%
→ secondary asset 15~30%
→ rare accent 5~10%
```

- 군락 중심, 바람 방향, 밀도와 크기 분포를 저장한다.
- 한 군락은 대표 실루엣 1개를 가져야 한다.
- 경계 바이옴에서는 모든 자산을 반반 섞지 않고 전이 전용 소수 종을 사용한다.
- LOD2에서는 개체가 아니라 군락 덩어리로 읽히게 한다.

### 16.2 접지

- 모든 암석과 식생은 지면 법선과 무게 중심을 고려한다.
- 큰 암석은 5~15% 정도 지면에 묻어 떠 있는 인상을 없앤다.
- 기부에는 작은 퇴적, 색 변화 또는 뿌리 연결을 둔다.
- 경사면에서는 아래쪽 파편과 토사 누적을 함께 배치한다.
- 제거 가능한 소품은 기초 배치 시 충돌과 시각 인스턴스가 같은 ID로 제거된다.

### 16.3 바람 애니메이션

- 모든 식생은 공통 풍향 필드를 사용한다.
- LOD0에서만 부위별 위상차를 사용한다.
- LOD1은 전체 기울기만 사용한다.
- LOD2와 원경 군락은 정적이다.
- 암석, 줄기 기부와 두꺼운 구조는 흔들리지 않는다.
- 날씨 변화는 진폭보다 돌풍 주기와 방향 변화로 먼저 전달한다.

## 17. Blender 자동화 파이프라인

### 17.1 Codex가 수행할 수 있는 작업

Blender 설치 후 다음 작업을 CLI와 Python으로 자동화할 수 있다.

- `.blend` 템플릿과 컬렉션 생성
- 절벽, 암석, 식생과 랜드마크의 절차적 blockout
- Geometry Nodes 그룹 생성과 파라미터화
- 이름, 원점, 축, 스케일, UV와 커스텀 프로퍼티 검사
- LOD 생성과 수동 보정 후보 표시
- 충돌 메시 생성
- 공용 재질 연결
- glTF/GLB 내보내기
- 턴테이블·실루엣·정면·측면·상면 렌더
- 삼각형, 재질, 텍스처, 바운드와 파일 크기 보고서 생성
- World Studio에서 확인할 manifest 생성

형태의 미감이 중요한 영웅 자산은 자동 생성 후 Blender 화면 또는 렌더 프리뷰를 보며 수동 조형 판단을 반복한다.

### 17.2 실행 방식

```powershell
blender --background art/blender/environment/rocks/env_rock_basalt_column_a_src.blend `
  --python tools/blender/validate_asset.py `
  --python-exit-code 1

blender --background art/blender/environment/rocks/env_rock_basalt_column_a_src.blend `
  --python tools/blender/export_glb.py `
  -- --asset-id env_rock_basalt_column_a
```

Blender 실행 파일 경로는 프로젝트 설정 파일에 기록하고 사용자 홈이나 시스템 전역 변수를 덮어쓰지 않는다.

자산 전달은 다음 순서로 고정한다.

```text
.blend 원본
→ Blender scene validation
→ work/assets/raw의 비압축 GLB
→ Khronos glTF validation
→ dedup / prune / weld / quantize
→ Meshopt와 KTX2 선택 적용
→ 최종 GLB 재검증
→ content hash URL과 generated manifest
→ World Studio와 실제 게임 smoke test
```

- 첫 수직 절편은 비압축 GLB로 좌표, pivot, material, LOD와 loader 계약부터 검증한다.
- Meshopt와 KTX2는 로더·브라우저 smoke test가 통과한 뒤 기본값으로 바꾼다. Draco와 Meshopt를 동시에 운영하지 않는다.
- 로컬과 자동화 환경의 Blender minor version을 프로젝트 파일로 고정한다.
- export 대상은 이름순으로 정렬하고 사용자 경로, 시간값과 현재 선택 상태가 결과를 바꾸지 않게 한다.
- 같은 원본 hash와 도구 버전의 export 구조가 달라지면 자동화가 실패해야 한다.

### 17.3 자동 검증 항목

- 자산 ID와 파일명이 규칙과 일치한다.
- 모든 필수 LOD와 충돌 컬렉션이 존재한다.
- 미적용 transform과 음수 스케일이 없다.
- 원점과 바운드가 규정 안에 있다.
- degenerate face, non-manifold edge와 뒤집힌 normal을 보고한다.
- 재질 수와 텍스처 해상도가 예산 안에 있다.
- LOD 삼각형 비율이 감소한다.
- glTF export 후 다시 불러왔을 때 노드명과 extras가 보존된다.
- 렌더와 런타임의 바운드, 축과 재질색이 일치한다.

## 18. glTF와 Three.js 런타임

### 18.1 전달 형식

- 런타임 모델은 기본적으로 단일 `.glb`를 사용한다.
- 애니메이션, LOD, 소켓과 metadata를 같은 자산 계약으로 전달한다.
- 반복 소품은 같은 geometry/material을 공유하고 `InstancedMesh`로 배치한다.
- 고유 영웅 자산은 일반 scene graph로 로드한다.
- 자산 로더는 경로별 Promise 캐시와 참조 카운트를 가진다.

### 18.2 압축

- geometry는 Meshopt를 우선 검토하고 디코드 비용과 크기를 비교한다.
- 텍스처는 KTX2를 사용한다.
- 단순 소품은 양자화와 인스턴싱을 적극 사용한다.
- 압축 전후 normal, tangent, UV와 애니메이션이 동일한지 자동 비교한다.
- 개발 모드에서는 비압축 자산도 빠르게 교체할 수 있게 한다.

### 18.3 로딩과 스트리밍

- 현재 청크와 인접 청크의 LOD0/1만 우선 로드한다.
- 원거리 LOD2는 작은 공용 번들로 먼저 로드한다.
- 동굴 자산은 입구 접근 전 프리패치하고 지상에서는 렌더하지 않는다.
- 사용하지 않는 texture, geometry, material은 명시적으로 dispose한다.
- 자산 로딩 실패는 프리미티브를 조용히 보여 주지 않고 개발 경고와 명확한 대체 실루엣을 사용한다.

### 18.4 현재 프로젝트에서의 전환 계약

현재 환경 소품과 설비는 동기식 Three.js geometry factory가 중심이므로 GLB 파일만 추가해도 자동으로 교체되지 않는다. 다음 순서로 수직 경로를 하나 먼저 닫는다.

1. generated manifest만 URL을 소유하는 `AssetManager`를 만든다.
2. 같은 자산의 Promise, geometry와 material을 캐시하고 인스턴스만 분리한다.
3. 기존 절차 모델 root는 위치, 선택, 게임 상태와 `userData`를 유지하는 placeholder로 남긴다.
4. GLB가 준비되면 visual child만 교체한다. 로딩 때문에 시뮬레이션이나 저장 형식을 비동기로 바꾸지 않는다.
5. Blender의 `VIS_LOD0/1/2` 그룹을 기존 거리 판정에 실제로 매핑한다.
6. 환경 반복 소품은 GLB hierarchy를 수백 번 복제하지 않고 geometry/material template을 `InstancedMesh`에 공급한다.
7. 압축 디코더, 네트워크와 GLB 검증 실패 시 명시적인 개발용 fallback을 표시한다.

GLB의 socket, collision과 extras는 시각 계약 검증에 사용한다. footprint, 자원 규칙, 포트 방향과 생산 수치의 권위는 계속 TypeScript 게임 데이터에 있으며, 둘의 불일치는 build 실패로 처리한다.

## 20. 화면 성능 예산

### 20.1 전체 예산

| 항목 | 고품질 | 저품질 |
| --- | ---: | ---: |
| 목표 FPS | 60 | 30 이상 |
| 총 드로우콜 | 220 이하 | 150 이하 |
| 총 화면 삼각형 | 700k 이하 | 350k 이하 |
| 환경 삼각형 | 420k 이하 | 190k 이하 |
| 공장·물류 삼각형 | 220k 이하 | 120k 이하 |
| 투명·FX 삼각형 | 60k 이하 | 40k 이하 |
| 동적 그림자 거리 | 40~48m | 20~28m |
| 그림자 캐스터 | 80 이하 | 36 이하 |
| 활성 환경 인스턴스 | 2,500 이하 | 1,000 이하 |
| GPU 텍스처 메모리 목표 | 160MB 이하 | 80MB 이하 |
| 전체 환경 업데이트 CPU | 평균 3ms 이하 | 평균 2ms 이하 |

평균 FPS만으로 승인하지 않는다. 고정 seed, 카메라와 날씨를 사용한 30초 캡처에서 데스크톱 고품질 `p95 ≤ 16.7ms`, 저품질 `p95 ≤ 33.3ms`를 함께 확인한다. 기준 스트레스 장면은 공장과 벨트를 포함하고, 환경 소품은 최소 500개, 표준 설비는 40개 이상을 배치한다.

### 20.2 품질 프리셋 연동

품질 변경은 다음을 한 번에 조절한다.

- terrain LOD 반경과 far terrain 해상도
- 소품 밀도와 LOD 전환 거리
- 그림자 거리, 해상도와 캐스터 수
- 구름 레이어와 렌더 해상도
- 물 반사 해상도와 갱신 주기
- 날씨 입자와 투명 효과
- 지면 데칼과 근거리 micro detail
- 화면 픽셀 비율

성능이 부족할 때 영웅 실루엣과 건설 가독성을 먼저 줄이지 않는다. 그림자, 투명 효과, 미세 데칼과 작은 소품부터 줄인다.

## 21. 디테일 제작 워크플로

### 21.1 자산 하나의 반복 과정

1. 역할과 물리적 형성 원인을 한 문장으로 정의한다.
2. 검은 실루엣 3안을 만든다.
3. 1인칭, 20m, 60m 썸네일에서 비교한다.
4. LOD2 형태를 승인한다.
5. LOD1의 중간 구조를 만든다.
6. LOD0의 근거리 구조를 만든다.
7. collision, socket과 FX point를 추가한다.
8. UV와 공용 재질을 적용한다.
9. GLB를 자동 export하고 검증한다.
10. World Studio에서 실제 지형·하늘·안개 아래 검수한다.
11. 성능 수치를 기록한다.
12. 승인 캡처와 manifest 버전을 저장한다.

### 21.2 지형 한 구역의 반복 과정

1. 회색 거시 지형으로 이동과 공장 배치를 검증한다.
2. 절벽, 물과 주요 군락을 추가한다.
3. 바이옴 재질과 중간 암반을 추가한다.
4. 1인칭 근거리 디테일을 추가한다.
5. 맑음, 황혼, 폭풍에서 가독성을 검증한다.
6. 지형 연속성과 필수 자원 접근을 자동 테스트한다.
7. 오버뷰와 1인칭 성능을 측정한다.
8. 작은 디테일을 줄인 상태와 비교해 실제 기여도를 확인한다.

## 22. 구현 우선순위

### P0: 구조 결함 제거

## 23. 완료 판정

### 23.1 지형

- 지정된 모든 카메라 경로에서 구멍, 균열, 빈 원경과 LOD 팝이 보이지 않는다.
- 색을 제거해도 여섯 바이옴 중 현재 위치를 지형 형태로 구분할 수 있다.
- 실제 절벽 수직면, 습지 수면과 자연스러운 해안선이 존재한다.
- 시작 공장과 모든 필수 자원 사이에 유효한 건설 경로가 존재한다.
- 렌더 높이, 충돌 높이와 건설 판정 높이가 일치한다.
- 1,000개 무작위 청크 경계 표본에서 높이 오차 1mm 이하, 법선 각도차 1° 이하이며 NaN·뒤집힌 면이 0건이다.
- CPU `TerrainSampler`와 렌더 정점의 높이 오차가 2cm 이하이고, 배치 preview와 실제 설치 판정 불일치가 0건이다.

### 23.2 오브젝트

- 원뿔, 원통과 토러스 한 개만으로 읽히는 최종 랜드마크가 없다.
- 자산마다 LOD0/1/2와 단순 충돌이 존재한다.
- 1인칭에서 접지, 두께, 재질과 형성 원인을 설명할 수 있다.
- 60m에서 종류와 방향이 실루엣으로 구분된다.
- 반복 배치가 원형·격자·동일 회전 패턴으로 드러나지 않는다.
- glTF Validator error가 0건이고 LOD, 재질, 텍스처, 충돌과 파일 크기 예산을 모두 통과한다.
- 네 방향 LOD 전환에서 위치 점프가 5mm 이하이고 화면상 2px를 넘는 실루엣 pop이 없다.

### 23.3 동굴과 물

- 동굴 내부에서 외부 하늘이나 지상 소품이 누출되지 않는다.
- 출구, 심층 방향과 건설 가능한 방을 HUD 없이 추적할 수 있다.
- 물은 수면, 깊이, 해안선과 젖은 지면의 네 층으로 읽힌다.
- 물과 동굴이 없는 구역에서는 관련 렌더 비용이 발생하지 않는다.

### 23.4 하늘과 날씨

- 맑은 날은 파란 하늘과 읽을 수 있는 흰 구름을 가진다.
- 주황 대기는 일출·일몰 또는 특정 날씨에서만 나타난다.
- 맑음 상태에 상시 먼지 막이 존재하지 않는다.
- 날씨는 하늘, 구름, 안개, 지상 입자와 젖음을 함께 변화시킨다.

### 23.5 파이프라인

- Blender 원본에서 GLB, manifest와 thumbnail을 한 명령으로 생성할 수 있다.
- export 검증 실패 시 런타임 자산이 갱신되지 않는다.
- 동일 자산을 다시 export해도 이름, 축, scale과 metadata가 안정적이다.
- World Studio와 실제 게임이 같은 월드 데이터와 GLB를 읽는다.
- 목표 화면 성능 예산을 만족한다.
- 같은 `.blend` 원본과 도구 버전의 재export가 동일한 node, extras, LOD, texture와 animation 계약을 만든다.
- 자산 clone 하나를 제거해도 공유 geometry/material은 남고, 마지막 owner가 사라질 때만 정확히 dispose된다.

## 24. Blender 설치 후 첫 작업

Blender 설치가 끝나면 다음 순서로 파이프라인을 검증한다.

1. `blender --version` 또는 설치 경로의 실행 파일로 버전을 확인한다.
2. 프로젝트용 Blender 실행 경로를 설정한다.
3. `art/blender/templates/environment_asset_template.blend`를 만든다.
4. `tools/blender/bootstrap_scene.py`와 `validate_asset.py`의 최소 버전을 만든다.
5. 현무암 중형 암석 한 종을 LOD0/1/2와 충돌까지 제작한다.
6. GLB로 export한다.
7. World Studio 자산 검사 뷰에서 pivot, scale, 재질, LOD와 충돌을 확인한다.
8. 1인칭·20m·60m 렌더를 비교한다.
9. 이 한 종이 완성 기준을 통과한 뒤 절벽과 식생 키트로 확장한다.

첫 검증 자산은 영웅 랜드마크가 아니라 중형 현무암을 선택한다. 규모가 작고 접지, 재질, LOD, 충돌, 인스턴싱과 export 계약을 모두 검증할 수 있기 때문이다.
